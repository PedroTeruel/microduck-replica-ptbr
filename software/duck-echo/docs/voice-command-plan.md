# R3 中文语音动作（2026-10-25）

用户选择按住手柄键说话、松开执行，继续通过 SSH 更新。保留现有 R3 复读：明确识别到坐下或站起来时执行，其余话语继续复读。

## 设计

- 使用 Vosk small-cn-0.22 本地中文模型（官方约 42 MB），不上传录音。模型常驻后台识别线程，只在 R3 松开后处理一段有限录音。
- 采用小词表，保留未知语音、否定和引用形式。完整听写在板端需 6–7 秒；小词表在同板 14 条合成语音上约 0.26–0.51 秒。
- 白名单仅坐下和站起来及少量明确同义词。完整句子去空白、标点后精确匹配；“不要坐下”“坐下再站起来”和低置信度结果不触发动作，不采用模糊匹配。
- 普通说话、明确“复读”前缀和没有识别到口令的录音沿用复读。启动新录音、手柄断线或退出服务时取消尚未执行的旧口令；处理超过 6 秒的结果不得执行。录音达到 10 秒上限时取消本次，不自动执行。
- 每次执行先读取 robot.policies 和 robot.busStatus。已经坐着时再次说坐下不发送切换；已经站着时再次站起不切换。软着的站起走 robot.init；坐着且策略正常时站起走 sit_toggle。
- 从站立保持状态坐下，先检查已 HOME、扭矩确认，再清零速度、通过 robot.enable 开启策略、等待读回后请求 sit_toggle。主程序拒绝任何一步就停止；不改固件、运动配置、标定和安全闸。
- 坐着且已卸力时不强行初始化或绕过现有主程序的姿态规则。动作回执和目标坐立状态分别检查。
- 只修改 /opt/duck-echo 和其服务；可关闭语音模式返回纯复读。模型、依赖隔离安装，运动服务不重启。

## 文件与验证顺序

1. `voice_commands.py`：口令解析、有限 JSON-RPC、坐立状态动作；先写否定句、低置信度、幂等坐立和未知状态拒绝测试。
2. `speech_control.py`：Vosk 识别、有限队列、取消与过期；用真实模型和系统合成测试语音验证识别，用单元测试验证迟到结果不会执行。
3. `duck_echo.py`：仅在语音启用时挂接处理器；未启用时保留原行为；覆盖普通语句回退、超时取消和断线取消。
4. 安装脚本及服务：安装两个模块，隔离依赖及模型路径，增加语音模式所需内存预算；通过现有回滚机制更新。
5. Linux 测试、真实模型测试、服务配置验证完成后上机。核对 CPU/内存、只读动作状态和模型加载；先观察识别，再由真实 R3 口令验证坐下和站起，复核原运动进程没有重启。
