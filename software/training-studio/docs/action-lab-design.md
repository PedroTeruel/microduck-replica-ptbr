# 动作实验室：单脚平衡

日期：2026-10-23。用户已授权在现有训练台内实现首个零代码动作玩法。

## 用户流程

首页的「动作实验室」入口打开现有新建训练抽屉，选择「单脚平衡」。保持四项主导航，不另建产品或服务器。用户选择支撑脚（机器人自身左/右）、另一只脚抬高多少、保持多久；进阶训练参数仍折叠。现有平地/起伏地形配方保留。

三维目标示意展示左右脚和抬脚方向，并标注「目标示意 · 非训练结果」。绘图不宣称精确运动学或平衡验证。已创建实验保存动作参数，参数只读；复制实验或短试跑转正式训练沿用参数。修改动作目标需要新的匹配短试跑。实际策略效果只来自选定检查点的物理评估视频。

## 固定接口

- 配方 `hd1910-single-leg`，任务 `Mjlab-Balance-Flat-MicroDuck-HD1910`，实验目录 `microduck_hd1910_balance`。
- 请求及记录新增 `skill` 对象：`support_side` 为 `left/right`；`lift_height_m` 为 0.005–0.02、默认 0.01；`hold_seconds` 为 1–5、默认 3。拒绝布尔数值、非有限值、未知字段、行走配方夹带技能参数。
- 配方元数据增加 `experiment_name`；单脚配方提供 `skill_defaults` 和 `skill_limits`，前端按后端范围展示厘米与秒。新配方默认 256 环境、1000 轮、25 轮保存；短试跑仍强制 64 环境、5 轮、每轮保存。
- 动作参数加入短试跑匹配、恢复、导出来源及评估。旧行走记录没有 `skill` 时保持兼容；不接受任意任务名、路径或命令片段。
- 每个配方的日志目录从服务端白名单取得，训练日志识别、PT 扫描、恢复路径、评估/导出检查点校验必须一致。

## 训练引擎

从 HD1910 速度配置深拷贝，保留 Feetech BAM、61 维观测、14 维动作、50 Hz、NaN 防护与匹配物理随机化。新增专属命令、奖励和阶段进度；删除会抵消抬脚或改写命令的步态奖励/课程。左右只训练所选支撑脚，不启用无条件镜像损失。

动作包括稳定、抬脚、保持、落脚、双脚稳定结束；完整周期和参数随实验固定。奖励及成功判断必须检查正确支撑脚、抬脚高度、躯干姿态、滑移、禁用身体接地、落脚恢复，防止跌倒后脚离地骗取奖励。新命令语义另行记录，不能仅因输入输出维度相同就声称旧机器人运行时可直接使用。

训练 CLI 使用类型化命令配置字段传递参数；评估、导出在创建环境前用同一校验函数应用保存参数。保留现有归一化导出路径，不改依赖锁文件，不改变既有行走配方行为。

## 验收

1. CPU 配置/奖励测试：范围、左右映射、阶段边界、终止/成功门控、有限值、61/14/50 契约、旧工厂隔离；检查候选姿态和几何能支持目标。
2. 服务回归：匹配短试跑、旧记录、配方隔离路径、错误参数、暂停/续训、导出参数与来源。
3. 前端：草稿、单位换算、左右切换、短试跑门禁、复制、结果展示与移动布局。目标示意不得成为评估凭证。
4. 真实 GPU：64 环境 5 轮、保存 PT、按完整周期多次评估、真实视频、导出 ONNX 并核对推理。记录实际成功次数；训练退出成功不等同于动作成功。
5. 集成回稳定工作区，保留既有实验和服务状态。只在没有活动任务时重启服务。

## 边界
