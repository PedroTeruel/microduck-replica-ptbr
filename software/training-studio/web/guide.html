动作实验室：从第一个动作开始

适用：HD1910 Microduck · 2026-10-23

1. 零基础先这样玩

从左侧导航或训练台首页进入「动作实验室」。这是独立的动作配方库：可以搜索、按分类筛选、查看预览或文字说明。选择「单脚平衡」后使用这个配方，先用推荐目标：左脚支撑、另一只脚抬高 1 厘米、保持 3 秒。左右以机器人自身为准。

  1. 选一个动作目标。 调整支撑脚、抬脚高度和保持时间。三维图帮助理解目标，不是物理仿真或训练结果。
  2. 点「开始短试跑」。 使用 64 个环境、5 轮，确认环境、训练和保存正常工作。几轮试跑通常学不会这个动作。
  3. 试跑通过后开始正式训练。 可以先保留推荐参数。轮数进度表示计算做了多少，不表示学会了多少。
  4. 选检查点，再点「评估」。 平衡评估运行 8 次尝试，每次包含准备、抬脚、保持和落脚。查看成功次数和实际回放。
  5. 根据回放调整。 先从低抬脚、短保持开始；改变目标后重新短试跑。保存不同实验，比较各自的目标和结果。

没有检查点评估视频时，转动三维小鸭不能判断它是否已经学会。演示模式使用合成数据，只用于熟悉页面；练动作需要真实 GPU 模式。

已训练好的模型与官方 V8

动作实验室的「预训练模型」页签收录官方 V8 策略集合和 kissqy V167 发布的 HD1910 模型。可以按来源、动作类型或关键词查找，查看版本、硬件、检查点编号、获取地址和许可。部分 kissqy 权重在其完整发布包内，详情列出包内位置。

官方策略集合已到 V8，但本训练台新建实验仍从零训练，不会自动载入 V8。 官方 V8 清单适配 XL330；kissqy 自训版本适配 HD1910，这两类权重不能仅凭名称或相同输入维度互换。V8 默认 VelStand 包含行走、零速站立和倒地恢复，集合中还保留早期独立行走/站立模型。官方 V8 清单

「获取 ONNX」打开发布者的权重文件；「查看发布包」打开原始包页面，不会自动安装或修改机器人。当前目录尚未提供外部模型的本地仿真评估或续训。ONNX 用于推理，没有完整 PPO 训练状态；继续训练需要兼容的 PT 检查点、配置与归一化等数据，不能把 ONNX 当作同一个文件上传。

训练时看哪些数据

详情页的「执行端资源」显示当前 GPU 型号、占用、温度、显存，CPU 型号、占用和温度，以及内存用量。约每 3 秒刷新；读取不到的项目会显示原因。WSL 的 CPU 温度通常不可读，CPU/内存是虚拟机可见范围，GPU 是整卡读数，包含其他进程。查看已结束实验时，资源数据仍是此刻的机器状态，不是那次训练的历史占用。

训练轮数与采样速度来自该实验日志。刚启动、还没有输出第一轮时暂时没有吞吐量；结束实验保留最后一次已记录指标。轮数不是物理仿真步数，也不是动作成功率。

2. 三个选项是什么意思

选项 当前范围 含义
支撑脚 左脚 / 右脚 这只脚留在地面，另一只脚抬起
抬脚高度 0.5–2 厘米 抬起脚的脚底相对地面的目标距离
保持时间 1–5 秒 满足站稳条件时持续保持，不是整个动作总时长

动作顺序为：双脚准备 → 抬脚 → 保持 → 落脚并恢复双脚支撑。完整周期约为「保持时间 + 3.5 秒」。这定义了任务目标；策略自己寻找关节控制方法，不照抄预览姿势。

这是实验性仿真配方。模型可以达到这些抬脚高度，但不证明策略能够稳定完成，也不证明实物具有相同表现。质量、惯量、供电和舵机误差仍会影响结果。导入鸭子档案用于记录核对，当前不会自动改写物理模型。

3. 怎么判断真的学会了

奖励曲线上升表示策略更符合训练评分。动作验收另外检查：指定脚持续支撑、另一只脚离地、身体姿态和速度受控、保持足够时间，最后恢复双脚支撑。倒下后脚悬空、瞬间抬脚或保持后摔倒都不能算完整成功。

报告保留每次尝试的结果、保持时间和失败原因，视频包含所有尝试。0/8 也会如实显示。8 次是便于反复检查的小样本；部署前还需要更多初始姿态、扰动和实机验证。

回放里的现象 下一步
一开始就倒 检查模型、任务和数值；不要只增加轮数
能站住，没有抬脚 检查目标与训练进展，尝试更低的目标
抬起后很快放下 先缩短保持时间，检查支撑与倾斜条件
保持完成，落脚时倒下 返回阶段尚未学好，完整动作仍算失败
分数高，动作却不对 保留视频和配置，调整任务规则，不能用分数代替验收

暂停会保留进程和显存。关闭浏览器不会结束训练；暂停也不会自动关闭云电脑或停止平台计费。停止后可以从已保存的检查点继续。

4. 想玩更多奇怪动作怎么办

不需要先学会写代码，也不必先用 AI。 已接入的动作可以直接选模板、改参数、运行和看回放。完全新的动作需要先把任务规则接入引擎；现阶段不能输入一句话就自动训练任意动作。

动作实验室的后续方向是社区共建的动作配方库：作者写好动作目标、训练规则和验证方法，经过审核后收录；其他用户选择配方并调整参数，就能自己训练。目前提供三个内置训练配方和二十个上游预训练模型条目。模型通过原发布方获取；社区网页投稿和自动安装还未实现。

想法 当前入口或下一步
左脚站、右脚站，改变高度和时间 动作实验室的单脚平衡
平地行走、适应起伏地形 现有行走配方
摆头、招手、固定顺序表演 可考虑关节关键帧编排；本训练台暂未提供这个编辑器
跳一下再站稳 尚未接入；先检查舵机输出和落地条件
精准转满一圈后停下 尚未接入；需累计转角与停止条件
上传舞蹈视频让小鸭模仿 暂不支持；需要动作映射和模仿训练

描述新动作时，写清：从什么姿势开始 → 哪个部位怎么动 → 保持多久 → 最后停在哪个姿势 → 什么情况算失败。例如：“双脚站好，右脚支撑，左脚抬起 1 厘米，保持 2 秒，再双脚站好，期间不能靠头撑地。”

5. 官方是怎么训练的

官方使用 PPO 强化学习，在大量仿真环境里尝试动作，通过奖励调整策略，再导出 ONNX。开发新动作时，先选相近任务、确认物理条件、定义目标与验收，再做短试跑。官方项目 · 官方开发指南

训练台把已实现的任务包装成可选配方。单脚平衡是本仓库新增的 HD1910 实验任务。官方还有 SitStand、StandUp、BallKick、Roulade 等任务，但需要适配 HD1910；Spin 使用轮滑模型，不能直接套在当前脚掌上。官方任务注册表

6. 进阶：自己添加动作

只想试已有动作，可以跳过这一节。

  1. 测量模型、关节范围、执行器和接触，确认目标可达，再验证扰动后能否站稳。
  2. 从 HD1910 配置复用执行器与观测接口，新增任务和独立实验名。
  3. 定义目标命令、奖励和失败条件；成功判定独立于奖励，并覆盖最后的恢复阶段。
  4. 测试配置、左右脚、边界值以及“错误动作不能成功”。
  5. 跑 64 环境、5 轮，检查日志、检查点、完整周期评估和导出。
  6. 先练容易的目标，再根据回放决定是否提高难度。
  7. 接入有限的动作参数，保证训练、续训、评估和导出使用同一目标。

以下路径相对于 software/training/：

文件 作用
src/mjlab_microduck/balance_parameters.py 参数、周期、成功判定和命令约定
src/mjlab_microduck/tasks/microduck_balance_env_cfg.py HD1910 平衡环境与实验配置
src/mjlab_microduck/tasks/mdp.py 命令、奖励和物理测量
src/mjlab_microduck/tasks/__init__.py 任务注册
scripts/export.py 保留观测归一化与目标导出

训练台配方在 software/training-studio/training_studio/config.py。日志与检查点按配方解析目录；只增加网页卡片不能形成可训练动作。

7. 命令行短试跑

适用于依赖已准备好的 Linux / WSL2，在 software/training/ 目录执行。以下命令会真实占用 GPU。

uv run --frozen list-envs

uv run --frozen train Mjlab-Balance-Flat-MicroDuck-HD1910 \
  --env.scene.num-envs 64 --agent.max-iterations 5 \
  --agent.save-interval 1 --agent.logger tensorboard \
  --env.commands.twist.support-side left \
  --env.commands.twist.lift-height-m 0.01 \
  --env.commands.twist.hold-seconds 3

本地依赖冻结为 mjlab 1.3.0，上游版本见 UPSTREAM.md。网上最新文档中的任务名不代表本地支持，以当前 list-envs 为准。

8. 导出后还差什么

导出包保留检查点、动作目标、训练配置、评估证据和带观测归一化的 ONNX。平衡策略仍使用 61 维观测、14 维动作、50 Hz，但目标命令的含义已经改变。

维度相同不代表能直接装进现有行走控制器。 部署端需按包中的命令约定提供支撑侧、抬脚目标和动作阶段，并核对关节顺序、零位与输出。单脚平衡真机部署尚未完成验证；先确认仿真结果，再进行受控实机测试。

说明基于本仓库冻结训练环境。新增动作须完成适配与验证后才能加入训练配方。
