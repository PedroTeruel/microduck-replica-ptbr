## 系统框图

```
                ┌──────────────────────────────┐
                │   Radxa Zero 3W (RK3566)     │  65 × 30 mm
                │   Armbian · 内核 6.1.115      │  Pi Zero 形态
                └──┬────────┬─────────┬────────┘
      /dev/ttyS2   │        │ 40-pin  │ MIPI CSI
      1 Mbps TTL   │        │  I2C3   │
    ┌──────────────┘        │ 400kHz  └── IMX219 摄像头（转 90°）
    │                       │
    │              ┌────────▼─────────────────┐
    │              │  Pollen RPI Robot HAT    │  65×30mm 自制板(已开源)
    │              │   ├ TLV320AIC3104  0x18  │  音频 codec
    │              │   ├ BMI088   0x19/0x68   │  焊了但没用
    │              │   └ Stemma J5 → ToF 0x29 │  VL53L5CX/L8CX
    │              │  电池经此板供电            │
    │              └──────────────────────────┘
    │
════╪══════════ Dynamixel 总线 · Protocol V2 · 1 Mbps ══════════
    │
    ├── 15 × XL330   ID 左腿20-24 / 颈头嘴30-34 / 右腿10-14
    └── imu_to_dxl v2 板   ID 200   ← LSM6DSV16X
```

**核心设计**：一条总线搞定一切。IMU 不走 I2C，做成 Dynamixel 从机挂在Servo总线Superior，
和 15 个舵机在**同一次 `sync_read`** 里读出。电池电压也不用电量计，
直接读Servo报告 de 自身供电电压。

## 主控

| 项目 | 值 |
|---|---|
| 模块 | **Radxa Zero 3W** —— 市售模块，**不是定制载板** |
| SoC | **RK3566**（4× Cortex-A55 + Mali-G52 + NPU） |
| 尺寸 | 65 × 30 mm，Pi Zero 形态，40 针树莓派兼容排针 |
| 系统 | **Armbian**（Debian 系），vendor 内核 6.1.115 |
| 策略推理 | ONNX Runtime ≥1.23（装 1.28.0），`dlopen` 加载 |
| NPU 推理 | rknn-toolkit2 —— **Armbian 默认关闭**，需刷 overlay 并重启 |

> 依据：设备树 `compatible = "radxa,zero-3w", "rockchip,rk3566"`；
> 全仓库 "radxa" 出现 182 次。

### 为什么传闻说是树莓派

1. 自制板名字**就叫 "RPI Robot HAT"**
2. Pi Zero 形态 + 40 针树莓派兼容排针
3. 摄像头是**树莓派 Camera v2**（IMX219）
4. **原型阶段确实用的树莓派 Zero 2W** —— `robotd.toml` 注释：50 Hz 控制环
   *"is inherited from the prototype, where it was chosen on a Raspberry Pi Zero 2W"*

前身 Open Duck Mini v2 **至今仍用树莓派 Zero 2W**，因为它不做视觉e WebRTC 推流。

### 为什么必须 Linux SoC 而非 MCU

要同时跑：ONNX 策略推理 @50Hz、720p30 H.264 Hardware编码 + WebRTC 推流、
NPU 目标检测、GStreamer 拥塞Controle（占 7.6% 一个核）、蓝牙手柄 + 手机 App + WiFi。
**STM32 / ESP32 做不了。**

## 执行器 e 总线

| 项目 | 值 |
|---|---|
| 电机 | **Dynamixel XL330 × 15**（每个约 18 g） |
| Eletrônica层 | **单线半双工 TTL**（3 线：Dados + VDD + GND），3.3V |
| Protocolo | **Dynamixel Protocol V2** |
| 速率 | **1 Mbps**（EEPROM `baud_rate = 3`） |
| 端口 | `/dev/ttyS2` = RK3566 **UART2，M0 pinmux** |
| 挂载设备 | **16 个**：15 Servo + 1 块 IMU 板 |
| 控制环 | **50 Hz**，一次 `sync_read` 覆盖全部 16 个，寄存器 124–136 |
| Rust 库 | [`rustypot`](https://github.com/pollen-robotics/rustypot) |

> ❗ **不是 RS232，也不是 RS485。** RS485 是差分双线，Dynamixel  de  XM/XH 系列才用。
> XL330 是 TTL 单线半双工。全仓库搜 `rs485|rs232|direction pin` **零命中** ——
> 代码里没有方向Controle GPIO，方向切换由Hardware自动方向电路Concluído（在 HAT 板Superior）。

### Servo ID 分配

```
左腿   20 21 22 23 24    hip_yaw / hip_roll / hip_pitch / knee / ankle
颈头嘴 30 31 32 33 34    neck_pitch / head_pitch / head_yaw / head_roll / mouth
右腿   10 11 12 13 14    （左腿镜像）
IMU 板 200
```

**第 15 个舵机是嘴（ID 34，索引 9）。** 所有策略都是 `obs[1,61] → act[1,14]`，
动作向量**跳过这个索引** —— 嘴由Superior层逻辑Controle，不由策略Controle。

### 总线可靠性（Oficial实测）

| 指标 | 值 | 出处 |
|---|---|---|
| 丢包率 | **约 8 次/分钟 ≈ 0.27%** | *"Measured on a bench robot at ~8 drops a minute"* |
| 官方定性 | *"One dropped Dynamixel transaction is **ordinary**"* | `robotd/src/main.rs` |
| 症状 | 随机小抽搐（丢读导致策略停一拍回 hold 姿态） | 同Superior |
| 容错 | `COAST_TICKS = 3` 用上个好样本滑行 60ms | 同上 |
| 容忍上限 | `max_consecutive_errors = 10` | `robotd.toml` |
| 循环稳定性 | `missed=3` / 15022 ticks，保持 50.0 Hz | `roadmap.md` |
| IMU 数据变质 | 有专门的 `StaleImuTracker`，注释写 *"Known to happen"* | `bus.rs` |

总线利用率估算 **约 25%**（约 500 字节/tick ÷ 1 Mbps ÷ 20ms）——
**瓶颈不是带宽，是信号Completo性e单点故障**：单端 3.3V 信号、15 个Servo菊花链、
线束穿过动态弯折 de Pescoço、旁边就是电机 PWM 噪声源。

## 两块 Pollen 自研板（一块已Código aberto、一块需自绘）

### ① `imu_to_dxl` v2 —— 元件极少，最容易自己做

| 项目 | 值 |
|---|---|
| IMU 芯片 | **LSM6DSV16X**（ST 6 轴，带 SFLP Hardware姿态融合块） |
| 接口 | **Dynamixel 总线**（不是 I2C） |
| 总线 ID | **200** |
| 寄存器地址 | **124** |
| Controle环Leitura | 12 字节 |
| Completo诊断块 | 20 字节（另含original加速度、采样计数、状态标志） |

**12 字节块布局**

| 字节 | Conteúdo |
|---|---|
| `0..6` | gyro x/y/z，`i16` 小端，±500 dps，**17.5 mdps/LSB** |
| `6..12` | SFLP 四元数 x/y/z，**IEEE fp16**；`w = √(1 − x² − y² − z²)` |

**自己做é necessário**：LSM6DSV16X + 一颗小 MCU 做 Dynamixel V2 从机
（STM32G0/G4、CH32V203、ESP32 均可）+ 半双工 TTL 收发器，供电从总线取。

### ② Pollen RPI Robot HAT —— Oficial已Código aberto，直接打样

**65.0 × 30.9 mm，板厚 1.0 mm，4 层板**（取自Oficial KiCad  e  Gerber，见 [BOM](../BOM.md)）。STL 网格量出 de  65.02 × 30.02 × 0.84 是仿真近似值，**Inferior单不要用**。插 40 针排针。

| 器件 | I2C 地址 | Instruções |
|---|---|---|
| **TLV320AIC3104** | `0x18` | TI 音频 codec，I2S 数据 + I2C 控制 |
| **BMI088** | `0x19` / `0x68` | **焊了但没用**（注释原文 "dormant"） |
| **ToF** | `0x29` | 不在板上，经 **Stemma J5** 外接 |

- I2C：40 针 **pin 3 / pin 5**（`GPIO1_A0`=SDA，`GPIO1_A1`=SCL），**400 kHz**
- Superior拉：**单对 10k，R12/R13**
- 音频时钟：MCLK **12 MHz**，I2S sysclk **12.288 MHz**（256×48kHz）
- 麦克风接 **Mic3R**（单声道Direito PGA），其余输入全关
- **机器人内部供电经此板**

## 三个必踩 de 坑

1. **Armbian 默认在 UART2 上跑登录控制台** —— `serial-getty@ttyS2` 的 `agetty`
   会占着串口。必须 `systemctl mask serial-getty@ttyS2`。
   官方是用 `fuser -v /dev/ttyS2` 查出来的。

2. **i2c3  e  FUSB302 抢引脚** —— RK3566  de  i2c3 在原厂 DTB 里跑 M1 pinmux
   Serviço USB-C PD Controle器；用 pin 3/5  de  M0 就得禁用 fusb302，**失去 PD 协商**。
   好在 FUSB302 Superior电默认 CC 呈 Rd，普通 5V 充电仍然可用。

3. **NPU 默认关闭** —— Armbian 出厂不开，跑 rknn Modelo要刷 overlay 并重启。
