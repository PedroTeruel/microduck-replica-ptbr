## 3. 做了什么

### 3.1 UDP 手柄

**做法**：官方是另起一个服务 `netpadd`，和 padd 共用一个新拆出来的映射库。kissqy 的 padd 有他自己的按键映射，所以我们没有照搬，而是在 **padd 里加了第二个输入源**。数据报里的按键翻译成和蓝牙手柄一样的按键事件，摇杆、扳机也一样，蓝牙手柄能做的 UDP 手柄都能做，走的是同一份代码。好处是不用新增服务，不用改中控，也不用改安装包。

**怎么用**：
1. 在 `/etc/robot/feetech-ft5/robotd.toml` 里加：
   ```toml
   [netpad]
   enabled = true
   port = 4210       # 官方默认端口，duckctl 默认就发这里
   timeout_ms = 250  # 多久收不到就算断开；必须小于 [safety] deadman_ms（默认 500）
   ```
2. `sudo systemctl restart padd`。日志里看到 `netpad on — reading the pad from UDP` 就是开了。
3. 电脑上装好 [uv](https://docs.astral.sh/uv/)，插上手柄，运行 `uvx duckctl@0.17.1 udp-pad <鸭子IP>`。Windows、macOS、Linux 都行。

**要Atenção**：
- **开着 UDP 手柄时，蓝牙手柄和中控的网页手柄都不读**，padd 只读一个来源。改回 `enabled = false` 再重启 padd 就恢复。
- **局域网里没有鉴权**：同一Rede里谁能发到这个端口，谁就能开鸭子、让它卸力、让它关机。只在信任 de Rede里、用 de 时候开。
- `timeout_ms` 写成 0、写得不小于 deadman，或者 `port` 写成 0，新编的 robotd 会拒绝整个配置文件、起不来，和官方一样。
- padd 的 systemd 沙箱原来只放行 `AF_UNIX AF_NETLINK`，收 UDP 要加 `AF_INET`。已经装好的板子用 drop-in 补：`/etc/systemd/system/padd.service.d/zzzz-udp-pad.conf` 写 `[Service]` 和 `RestrictAddressFamilies=AF_INET`。

### 3.2 手柄掉线自动Sentar

正在开的手柄（蓝牙或 UDP）消失 **1 秒**后，鸭子叫一声（疑问的叫声），先问 robotd「是不是已经坐着」，不是就发 `sit_toggle` 坐下，被拒绝的话 5 秒内一直重试。手柄回来时打招呼。不到 1 秒的闪断不出声，也不坐。

- `sit_toggle` 就是 D-pad 下默认绑定的那个动作。**上机前先手动按一次 D-pad 下**，确认 HD-1910 上坐得下去。
- Modelo没开（站在 HOME、没按第二Inferior Start）时，robotd 会回「the policy is not driving」，padd 就当作没事可做，鸭子不动。
- 已经坐着时不会去发 `sit_toggle`，否则会把它「站起来」。

## 4. 审核查出来 de 问题（现象 → 原因 → 怎么办）

改完按约定开了一个 subagent 独立审核，一共 6 轮。abaixo是每轮查出来、已经修好 de 问题，审核都用脚本复现过：
