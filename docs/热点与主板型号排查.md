# A ausência de resposta de um servo impede a criação do ponto de acesso?

Não. Na imagem atual, `microduck-netcheck` gerencia o Wi-Fi e o ponto de acesso de recuperação. Esse serviço depende apenas do gerenciador de rede e da ordem da primeira inicialização; não depende do `robotd`, dos IDs dos servos nem de a IMU do barramento estar online. A inicialização cria primeiro a configuração do ponto de acesso e depois tenta identificar a IMU I²C. Mesmo sem encontrar uma IMU, a configuração do ponto de acesso é concluída. Verifique separadamente servos desconectados, IDs não configurados e problemas de rede sem fio.

## Confirme primeiro se a placa é Zero 3W ou Zero 3E

Segundo a [documentação oficial da Radxa](https://docs.radxa.com/en/zero/zero3/getting-started/preparation), **o Zero 3W tem Wi-Fi integrado; o Zero 3E não tem Wi-Fi integrado e usa Ethernet para se conectar à rede**. Se a placa for realmente um 3E, ela não poderá criar uma rede Wi-Fi sem hardware sem fio adicional.

A imagem de réplica atualmente publicada neste projeto é voltada principalmente ao Zero 3W. O boot completo, a Ethernet e o adaptador sem fio externo do Zero 3E ainda não foram validados. Usar o mesmo RK3566 não garante compatibilidade entre kernel, árvore de dispositivos e hardware de rede. No 3E, confirme primeiro que o sistema iniciou e reconheceu a Ethernet; com uma placa Wi-Fi externa, confirme também o driver e o suporte ao modo ponto de acesso. O script atual de configuração usa `wlan0`; se o adaptador externo aparecer com outro nome de interface, será necessário adaptá-lo.

## Se for possível entrar no sistema, leia estas informações primeiro

Pelo método disponível — cabo de rede, SSH ou terminal serial — execute os comandos abaixo, que apenas consultam informações:

```sh
cat /proc/device-tree/model
systemctl status microduck-firstboot microduck-netcheck NetworkManager --no-pager
journalctl -b -u microduck-firstboot -u microduck-netcheck -u NetworkManager --no-pager -n 80
```

- **Zero 3W sem `wlan0`**: verifique a revisão da placa, o driver sem fio e a árvore de dispositivos. Alterar o ID dos servos não fará a placa Wi-Fi aparecer.
- **`wlan0` conectado ao Wi-Fi de casa**: em outro dispositivo na mesma rede, acesse a porta `8000` do IP atual do robô. A ausência simultânea de um ponto de acesso de recuperação não significa que ele esteja offline.
- **`wlan0` existe, mas não está conectado**: confira os logs do NetworkManager e de `microduck-netcheck` para saber se o sistema está tentando usar uma rede salva, iniciar o ponto de acesso ou informar uma falha. A primeira inicialização e a tentativa de conexão levam algum tempo; não julgue a situação apenas pelos LEDs.
- **Ponto de acesso `Microduck-xxxx` iniciado**: conecte o telefone à rede e abra `http://10.42.0.1:8000/`. Mesmo que o telefone mostre “sem internet”, mantenha a conexão: o ponto de acesso serve para controle local.
- **Zero 3E somente com Ethernet**: confirme se a interface recebeu um IP e acesse o sistema a partir da mesma rede. A validação completa desse modelo de placa ainda não foi concluída; não é possível garantir que regravar o cartão ou atualizar o software resolva todas as incompatibilidades.

Ao compartilhar logs, inclua somente o estado dos dispositivos e serviços. Não publique a senha do Wi-Fi, a chave privada SSH nem uma chave de IA.

## Resposta curta para o grupo

“O ponto de acesso não depende do ID dos servos. Primeiro confirme se sua placa é 3W ou 3E: o 3E não tem Wi-Fi integrado e, sem um adaptador sem fio, não cria ponto de acesso; nossa imagem atual é voltada principalmente ao 3W. Depois de confirmar o modelo, verifique as interfaces de rede e os logs de inicialização.”
