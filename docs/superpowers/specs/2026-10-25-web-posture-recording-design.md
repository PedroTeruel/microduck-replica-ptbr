# 网页录制增加坐下与站起

用户已经明确回复：“对，把坐下和站起也录进去”。这是对原首版排除坐站的范围修正；沿用此前允许本地开发、测试、SSH 更新现有控制网址的授权，不重复询问执行许可。

完成记录：aa825fc 已实现并更新当前鸭子原网页，用户确认“能保存，回放坐站也正常”。389 项软件检查及部署/回退边界见[验收](../verification/2026-10-25-web-posture-recording.md)。

## 选择与边界

采用明确的“坐下／站起”目标步骤，并读取主程序实时状态决定是否需要切换和何时继续。直接记录 sit_toggle 按键可能因起始姿态不同反向执行；只按延时播放无法识别 rise 仍在执行，均不采用。此次不加入踢腿、翻滚、捡取、卸力/上力或模型切换。

入口仍是现有动作录制区。用户先站稳并开始走，再录制“坐下→等待→站起→等待”，结束、命名保存、选择回放。经过同样路径的网页十字下与遥控坐站按钮均可录制；记录经过实际检查并获 robotd 接受的目标。录制不因受控坐站而结束，空动作提示不能把有效坐站误报为空。可保留以坐着结束的单次记录；多次循环要求末态回到站姿，否则说明需录回站姿再循环。不自动补站起动作。

保存采用有版本的语义步骤白名单，不将任意 robot.do/init/enable 写入文件；旧的 v1 指令记录继续可读。新含坐站内容采用 v2，旧版本回退对 v2 不兼容的边界需在记录中说明。兼容性指纹继续包含实际 sitstand 模型与配置。

## 状态证据与执行

robot.policies.enabled 是启动配置常量；bus.policy_enabled 才是运行开关。坐站的 sitting 标志在开始坐下时立即变 true、开始起身时立即变 false；homed 也不是起身完成信号。主程序现有 robot.state.policy 会报告 sit、rise、walk/stand。通过 Studio 原有订阅提供该策略阶段、样本时间及实际/目标关节信息，不重启或修改 robotd。

坐站执行要求来源状态新鲜、策略已启用、扭矩确认、模型存在、无实体手柄冲突及原有保护通过。回放读取目标姿态：已达到目标时不再切换；不明确时终止，不重试 toggle。起身必须等待新鲜非 rise 的 walk/stand 阶段；坐下需要新鲜 sit/sitting 与关节实际/目标收敛的连续样本，不能仅凭切换回执或坐姿标志宣布完成。缺失阶段/位置证据、超时或未知执行结果均停止后续动作，保留明确原因。请求回复与样本按会话/代次和时间隔离，不能用旧样本或迟到回复恢复会话。

坐站步骤不能被迟到连续目标合并丢弃；到该步骤时暂停回放时间轴，确认完成后再继续。等待不产生后续摇杆/头嘴目标，不在下一轮补发旧帧。模型内容、状态异常、实体手柄、急停、切页、后台、失焦、断网与心跳超时继续中止后续输出，重连不续播。

普通暂停/停止不能物理取消已交给 robotd 的坐站。暂停停止连续控制并冻结时间轴，坐站仍由主程序完成；恢复须重新验证。停止或离开页面取消后续步骤，明确提示“当前坐站仍会完成”，不假称立即物理停止、不自动站回 HOME、也不自动卸力。仍在完成的坐站阻止新的自动会话；急停继续走现有卸力通道。

## 验收

新测试先失败再实现：只坐站也生成非空记录，网页按钮和十字下均被纳入，拒绝不保存，旧 v1 文件可读，语义字段严格验证；实际发送的回放顺序是 sit→stand 且不反向切换。单独 sitting/homed 变化不能提早续播，连续收敛及 rise→walk/stand 新样本才能推进；旧样本、超时、RPC 丢回执、取消、暂停/恢复、断线/重连、身份变化、有限循环与尾态不匹配均覆盖。原 205 项动作/手柄测试继续通过。真实 Studio+fake robotd+Edge 走通坐站录制、保存、单次和三次回放及 320/390/1440 布局。真机部署只更换匹配 Studio 文件并重启 Studio，保留 state 和其他服务；自动测试不主动移动真鸭子，真实效果交由用户确认。
