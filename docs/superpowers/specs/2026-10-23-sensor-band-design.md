# 摄像头与 ToF 状态卡

用户确认在电池、舵机、IMU、手柄、主板所在的状态栏加入摄像头和 ToF，主要显示在线状态，点击进入已有独立页面。顺序为电池、舵机、IMU、摄像头、ToF、手柄、主板。继续本地开发，不连接或更新板子，IMU 流程保持原样。

摄像头以独立本机 mediad socket 的只读 hello 检查服务响应，配置读取本身不能证明设备在线。服务正常且配置 camera 时显示“服务在线／点开确认画面”；test 显示“测试画面／视频服务在线”；服务未响应显示“未连接”，无设备证明不显示硬件已识别。ToF 收到完整新帧才显示在线，fake/sim 标明模拟，服务在线但尚无帧显示等待数据，明确 unavailable 显示未连接。错误、超时和未知单独处理。所有检查不请求视频帧、不建立 WebRTC、不启动或重启服务。

状态栏只在总览／手柄区域可见且浏览器前台时低频读取，每10秒一次，离开或后台取消请求和计时。过期读数清空，不沿用在线绿色。手机使用两列，最后主板占满一行；桌面七列，窄桌面分行，所有卡片可读无横向溢出。

用户同时询问“没硬件时自动不启动服务”是否完成。已审查当前镜像：firstboot 自动识别是 IMU；apply-rootfs 把 media source 改为 test，防止摄像头缺失崩溃但仍运行媒体服务；旧工具支持手动关闭 ToF／摄像头。这不等于硬件自动检测和按需启动。该系统策略尚未实现，本轮不把网页网络错误用作关闭系统服务依据。
