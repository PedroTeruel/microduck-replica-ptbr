## 这次新增的动作组织方式

推荐在现有模型库与组合动作之上扩展一份可调用动作列表，每项有稳定标识、名字、类型、适用状态、结束方式与所需模型。用户在网页选择“这个按键做什么”，也可为同一动作设置语音口令。底层执行方式分别处理，页面不用要求用户理解文件路径。

| 类型 | 例子 | 与现在的关系 |
| --- | --- | --- |
| 模型技能 | 用新版捡取模型执行捡取，或绑定已注册的新技能 | 模型导入/选用和五个技能键已有；模型要匹配执行合同，持续行走模型不等于单次技能。 |
| 程序功能或组合 | 变声复读开关、点头加叫声、打招呼 | 网页组合及独立语音服务已有部分能力；统一绑定尚未实现。 |
| 保存的回放 | 录一段操作，命名“展示一号”，按键触发 | 网页录制、命名和回放已实现；实体手柄/语音绑定仍是后续扩展，首版不含。 |

已有的“更换捡取模型”与“把 A 键改成另一动作”是两种操作，要分别显示；恢复默认键位不应删除模型或录制内容。Start、Select 等基础控制及 R3 录音的冲突处理需明确，不能把“所有键都可改”作为当前能力。

回放已经沿用 10-24 方案实现：网页开始录制 → 操作 → 结束命名 → 选择记录 → 播放 1/3/5 次。记录获准发送的意图及相对时间，继续由原主程序负责关节和平衡；相关模型或控制配置改变后拒绝旧记录回放。关节示教和精确空间轨迹属于后续独立研究。模型技能缺少可靠完成回读，录制时直接拒绝；普通手动技能保持原行为。

## 镜像与在线升级：建议采用共同的版本包

三种交付方式需要同时保留，但用途不同：

| 方式 | 用途 | 当前情况 |
| --- | --- | --- |
| SSH 安装 | 开发、排障、在一只鸭子上快速验证 | 现在可用，但修改必须进入源码、版本包与验收记录。 |
| 组件版本包 + 网页在线升级 | 已经装好系统的鸭子增加功能、修复软件 | 2026.10.27签名包与网页流程本地完成；现机仍需一次性SSH引导和实物验收。 |
| 基线系统镜像 | 新卡首次安装、恢复系统、必要的底层迁移 | 新20261027本地镜像已消费同一签名包并通过解压只读验收，尚未上机或公开发布。 |

新镜像和在线升级应使用 **同一份冻结版本清单与安装逻辑**。镜像是某一版本软件包安装在干净系统上的快照；已经使用的鸭子安装同一版本包，保留自己的数据。不是从开发中的个人 SD 卡直接复制所有状态作为公共版本。

建议按依赖拆分组件：系统底座（引导/内核/设备树）、兼容的飞特运行时、Studio 与匹配的 helper、语音服务及识别资源、动作模型。Studio/helper 有接口依赖时作为一组更新；与运行时不匹配的官方更新不能覆盖飞特/IMU 扩展。电脑端训练台独立发布，不装进鸭子的低算力系统。IMU 小板固件另有硬件升级流程，不承诺普通 Linux 软件包可以替代其烧录。

安装包至少描述版本、源码提交、CPU/系统/硬件要求、组件依赖与接口版本、文件哈希、配置结构版本、迁移/回退方式、需要重启的服务与是否必须重启系统。应有可信发布来源及包验证；先下载和校验、检查实际状态、保留旧版，再安装、检查服务及配置回读，确认成功后记录版本。失败不得把“已下载”或“服务启动命令成功”显示成“升级成功”。

原项目更新器设计：[updater-design.md](../../Microduck-kissqy/microduck-hd1910/firmware/docs/design/updater-design.md)。10-27已验证实际ARM引擎，建立独立software配置和自己的发行公钥；本轮只完成本地组件/镜像，未启用现机旧更新服务。飞特运行时与系统仍按独立合同处理。

网页可提供“当前版本 → 检查更新 → 更新内容/影响 → 用户点击升级 → 进度与结果 → 可用时退回上一版”。下载与实际切换分开；切换依赖鸭子处于允许状态，不能行走时后台自行替换运行时。核心服务更新通常会短暂停止相应控制，不宣传无中断热升级。

### 必须保留的用户数据

升级设计需要逐项覆盖：舵机零位/方向/限位与调好参数、IMU 安装方向和会话恢复数据、用户 Wi-Fi/手柄配对、登录与 SSH 设置、导入的模型、当前选用/按键映射、鸭子档案、已保存动作及语音偏好。配置迁移要验证旧版能否读回；无法向后兼容时明确回退边界。

公共镜像则必须清除个人 Wi-Fi 密码、SSH 密钥、主机身份、登录会话、配对与录制内容。F18 当前家中 SSID 只是这只鸭子的设置，不能作为公开默认值。
