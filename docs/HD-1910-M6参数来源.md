# Origem e aplicação dos parâmetros HD-1910 M6

Em 2026-09-24, o projeto adotou os **parâmetros dinâmicos BAM M6 do servo 1910 publicados pela LuwuDynamics** como modelo inicial para treinar a simulação do HD-1910. Agradecemos à LuwuDynamics por compartilhá-los. Esses parâmetros não foram identificados nem medidos por este projeto; nosso trabalho até agora é integrá-los e validá-los. O teste no robô real ainda será feito pelos mantenedores.

## Como usar

O código de treinamento, os parâmetros, o modelo e as correções de integração estão juntos em **[`software/training/`](../software/training/)**; clone ou baixe este repositório para obter o projeto completo. As [instruções de uso e o registro de validação](../software/training/docs/hd1910-baseline.md) incluem comandos, resultados de testes e a causa e correção do problema de inicialização do histórico do controle Feetech.

- O arquivo de parâmetros é preservado sem alterações, incluindo `model: "m6"` e `actuator: "sts3215"`; este último seleciona a implementação de controle Feetech do BAM. O upstream identifica o modelo como HLS1910; os mantenedores confirmaram que é o mesmo servo 1910.
- Configuração de treinamento associada: P=5, aleatorização de tensão entre 7,4–8,0 V, limite inferior de queda de tensão em 7,0 V e atraso de 3–6 passos da simulação. `max_velocity=100` libera a limitação da inclinação do alvo; não é a velocidade real sem carga do servo.
- Foram adicionadas entradas de treinamento independentes `Mjlab-Velocity-{Flat,Rough}-MicroDuck-HD1910`, para comparação com a referência original XL330. A integração atual preserva a geometria local do Microduck, a ordem das juntas e a pose padrão.
- Os zeros, sentidos e limites individuais do robô real continuam usando as calibrações deste projeto. Não copiamos os zeros de encoder do robô completo de terceiros nem uma ONNX pronta como política diretamente utilizável no robô.

## Limites da validação atual

A publicação desses parâmetros permite iniciar a integração à simulação sem exigir como etapa inicial a construção de uma bancada completa de identificação. Este projeto ainda não validou no robô real os parâmetros da Luwu. É preciso conferir o ganho local, a alimentação, o atraso de resposta, a massa e a inércia, a IMU e a temporização da comunicação com a placa principal. Primeiro, compare a simulação e o robô usando uma resposta a pequenos degraus; depois decida se será necessário fazer uma nova identificação.

Outros dados estáticos e dinâmicos necessários estão na [lista de dados antes do treinamento](HD-1910训练前数据清单.md). A referência de M6 indicada aqui é usada pela nova base de treinamento.

## BAM oficial HD-1910 da Feetech

Incluído em 2026-10-14. No fim de setembro, a Feetech publicou no Gitee o [ftservo/ftservo-bam](https://gitee.com/ftservo/ftservo-bam), uma derivação (fork) do [Rhoban/BAM](https://github.com/Rhoban/bam), sob Apache-2.0:

- **Parâmetros**: `bam/params/feetech_hd1910_7_4V/m1.json` a `m6.json`. A última alteração do arquivo m6 foi no commit `79eff6d` (09-26); SHA-256 `81a441fb921130bcc9bcfbd9ee0c77e3c38d9ab758bc7e0559fb029c436355ba`. A revisão HEAD do repositório no momento do registro era `4f7c0b0` (09-30).
- **Modelo de controle**: `HD1910Actuator` em `bam/feetech/actuator.py`, controle somente P: ciclo de trabalho = clip(0.163 × P × erro angular, ±0.97), alimentação de 7,4 V, sem limite de velocidade e sem D.
- **Identificação**: braço de alavanca com carga, P=4, 8, 16, 32 e 64, percorrendo quatro trajetórias de excitação (`bam/feetech/all_record.py`).

**Comparação com Luwu 1910 M6** (os cinco primeiros valores são calculados pela fórmula BAM; os demais vêm do JSON. Nenhum é medição nossa):

| Parâmetro | Luwu 1910 M6 | Feetech HD-1910 m6 |
|---|---:|---:|
| Modelo de controle | Reutiliza STS3215 (0,166 × ganho ajustado 1,32) | Específico para HD1910 (0,163) |
| Ciclo de trabalho por radiano de erro e por unidade de P | 0,219 | 0,163 |
| Erro a partir do qual satura em P=5 | 0,88 rad | 1,19 rad |
| Torque de bloqueio a 7,4 V | 0,91 N·m | 1,37 N·m |
| Rigidez estática para pequenos erros (P=5) | 1,03 N·m/rad | 1,15 N·m/rad |
| Resistência do motor R | 4,91 Ω | 2,97 Ω |
| Inércia de rotação `armature` | 0,00178 | 0,00183 |
| Atrito da carga no lado do acionamento `load_friction_motor` | 0,069 | 0,353 |
| Atrito da carga externa `load_friction_external` | 0,158 | 0,043 |
| Atraso do comando `command_delay` | 6,0 ms | 1,0 ms |

`command_delay` é apenas o valor registrado durante a identificação: a versão BAM fixada neste repositório não o usa no treinamento. O atraso é configurado separadamente por `delay_min_lag` / `delay_max_lag` (3–6 passos da simulação).

**Cuidados na integração**:
1. O JSON oficial informa `"actuator": "hd1910"`, mas a chave no registro é `"HD1910"`; a diferença entre minúsculas e maiúsculas causa `KeyError` ao executar `load_model`. No repositório Feetech, altere `actuator` para `"HD1910"`; também é possível abrir uma issue para a Feetech.
2. O coeficiente de conversão difere: o da Feetech é 0,163 (com P=1, um erro de 4.000 contagens corresponde a 100% de PWM; `1 / (4000 × 2π / 4096) ≈ 0,163`; vem de um documento antigo da Feetech, commit histórico `3c37f36`, removido posteriormente). O STS3215 original Rhoban usa 0,166. Para usar os parâmetros Feetech no projeto de treinamento deste repositório (Rhoban BAM fixado em `62bd8ce`), reutilizando o modelo de controle sts3215, ajuste três valores: `actuator` para `"sts3215"`; `error_gain_ratio` para 0,163 / 0,166 ≈ 0,98193; e `max_velocity` para 100, como no modelo Luwu, para liberar o limite de velocidade do alvo (sem isso, o padrão é cerca de 5,2 rad/s; o modelo Feetech não limita a velocidade). Com valor 100, o alvo ainda pode avançar no máximo 0,5 rad por passo físico, como no modelo Luwu; é uma aproximação.
3. O script de gravação `record.py` escreve apenas P (endereço 50 no HD-1910), velocidade-alvo 0 e posição-alvo; D, limite de torque e aceleração permanecem nos valores existentes no servo. Se D de fábrica for 40, é provável que o amortecimento de D seja incorporado aos parâmetros de atrito ajustados (hipótese não verificada). Antes de usar no robô um modelo treinado com esses dados, confirme D, de preferência com a Feetech.
4. Alguns parâmetros de atrito ficaram nos limites do ajuste: `load_friction_external_quad` = 0,0099999 (limite superior 0,01), `friction_stribeck` = 0 (limite inferior) e `load_friction_motor_stribeck` = 1,7e-6, também próximo do limite inferior. Isso não significa necessariamente erro, mas não se deve interpretar esses números diretamente como grandezas físicas.

O projeto de treinamento deste repositório ainda usa os parâmetros Luwu. A integração dos parâmetros Feetech foi revisada uma vez, mas ainda não foi implementada; também não comparamos no robô real qual conjunto é mais preciso.
