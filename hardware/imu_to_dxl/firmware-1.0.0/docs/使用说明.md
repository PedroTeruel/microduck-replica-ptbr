# 使用说明

Microduck IMU 板（STM32G031F8P6 + LSM6DSV16X）飞特 FT-SCS 总线固件的上位机操作手册。
IMU 板固定 **ID=200，1Mbps**，与飞特 SCS/STS 舵机共线，单条 SYNC READ 同时读取。

---

## 1. 系统组成与接线

### 1.1 总线拓扑

```
   USB 半双工适配器(COM6)
        │ 单线 DATA + VDD_BUS + GND
        ├── J1/J2 或 J4/J5 ── IMU 板 (ID=200)
        ├── 飞特舵机 (ID=2)
        └── 飞特舵机 (ID=3) ...
```

- 总线是**单线半双工**，所有设备（IMU 板 + 舵机）挂同一根 DATA 线，1Mbps、8N1。
- 总线供电 VDD_BUS 给舵机（本机实测 8.0V）；IMU 板自身按其硬件供电方式上电。
- 同一时刻**只能有一个主机**在发指令。运行工具前关闭飞特 FD.exe 等其他总线软件。

### 1.1.1 J1/J2/J4/J5 总线接口

| 接口 | 引脚 |
|---|---|
| J1/J2 | 1=GND、2=VDD_BUS、3=DATA |
| J4/J5 | 1=DATA、2=VDD_BUS、3=GND |

必须使用**单线半双工 USB 适配器**接到这里；普通 USB-TTL 串口不能直接驱动单线总线。

### 1.2 J3 调试日志口（DAP-Link 或 USB-TTL）

| J3 脚号 | 信号 | 接法 |
|---|---|---|
| 1 | GND | 共地 |
| 2 | SWDCLK | 调试器 SWCLK（仅烧录用） |
| 3 | SWDIO | 调试器 SWDIO（仅烧录用） |
| 4 | UART_RX | USB-TTL TX，3.3V（115200 日志） |
| 5 | UART_TX | USB-TTL RX，3.3V（115200 日志） |
| 6 | 3.3V | 调试器电压参考；**不要接 5V** |

- 日志串口 115200、8N1，开机应打印：
  `imu_to_dxl 1.0.0 | STM32G031F8 | FT-SCS ID=200 1000000 8N1`
- 之后每秒输出一行状态：`ready=1 id=0x70 ... gyro=... q16=... ck=0`。
- **DAP-Link 的 CDC 串口必须置高 DTR+RTS 才能收到数据**（串口助手勾选这两个硬件握手项）。
- J3 日志口**不响应**任何总线协议指令；协议操作必须走 COM6 总线适配器。

### 1.3 本机端口（Windows）

| 端口 | 用途 | 参数 |
|---|---|---|
| COM6 | 半双工总线适配器（协议操作） | 1000000 8N1 |
| COM5 | DAP-Link CDC 日志口 | 115200 8N1，需 DTR/RTS |

端口号以设备管理器实际枚举为准，工具用 `--port` 指定。

## 2. 软件环境

### 2.1 Python 上位机工具

需要 Python 3.8+（本机验证为 3.8.10 32 位）和 pyserial；`--plot` 另需 matplotlib。

```powershell
python -m pip install -r Tools\requirements.txt
```

Python 3.8 以上都行（`python --version` 看一下）
（注意不要用 Windows 应用商店的 `python.exe` 占位符）。

## 3. 固件构建与烧录

### 3.1 构建

VS Code 中按 **Ctrl+Shift+B**，或：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\build.ps1 `
  -ToolchainRoot 'C:\Keil_v5\ARM\ARMCLANG'
```

成功后产物在 `Build/`：`imu_to_dxl.hex`（烧录用）、`.bin`、`.axf`（调试用）、`.map`。
当前固件约 10.9 KB Flash / 5 KB RAM。

### 3.2 烧录（重要：用 OpenOCD，不要用 UV4 命令行）

**UV4 命令行烧录会"假成功"**：退出码 0、日志为空，但芯片实际没有擦写（可从日志 uptime
不复位看出）。请使用 OpenOCD（DAP-Link/CMSIS-DAP）：

```powershell
& 'openocd.exe' `   # 换成你电脑上 OpenOCD 的路径
  -f interface/cmsis-dap.cfg `
  -f target/stm32g0x.cfg `
  -c 'adapter speed 4000' `
  -c 'program Build/imu_to_dxl.hex verify reset exit'
```

注意：目标配置文件名是 **stm32g0x.cfg**（不是 stm32g0x0.cfg）。
烧录前关闭 Keil µVision（它会独占 DAP-Link HID）。SWD 接触不良时重插杜邦线即可。

### 3.3 烧录后验证

1. COM5 日志出现 `FT-SCS ID=200` 开机横幅且 `ready=1 ... ck=0`。
2. 运行扫描（见 4.1），应看到 ID 2、3（舵机）和 ID 200（IMU 板）。

## 4. 上位机工具

四个工具都在 `Tools/` 目录，统一 `--port COM6`、1Mbps。

### 4.1 servo_tool.py —— 舵机/总线扫描工具

```powershell
# 扫描 1..253，列出所有应答设备（舵机 + IMU 板）
python Tools\servo_tool.py scan --port COM6

# 监视单个舵机状态块（位置/速度/负载/电压/温度）
python Tools\servo_tool.py read 2 --port COM6 --watch

# 单舵机往返测试（会转动！默认 1024<->3072，3 个来回，结束自动关扭矩）
python Tools\servo_tool.py test 2 --port COM6

# 原始寄存器写（高级操作；对 IMU 板写 ID/波特率会被固件忽略）
python Tools\servo_tool.py write 200 84 90 --port COM6
```

扫描输出中 ID 200 显示 `model=0x4d44 fw=1` 即 IMU 板；其余为舵机。

### 4.2 imu_probe.py —— IMU 只读验收探针

最严格的验收工具：PING → 读身份 → 周期性读 56 起 40 字节数据块 + 90 起 96 字节诊断块，
输出 JSON、可存 CSV。**全程只发读指令，不会驱动任何舵机。**

```powershell
# 采 30 秒、50Hz，存 CSV
python Tools\imu_probe.py --port COM6 --seconds 30 --csv Build\imu.csv

# 额外用"单 ID 广播 SYNC READ"路径取快速块（验证 0x82）
python Tools\imu_probe.py --port COM6 --seconds 30 --sync

# 自定义采样率（1~100Hz）
python Tools\imu_probe.py --port COM6 --seconds 10 --hz 100
```

退出码为 0 表示：无通信错误且所有样本 ready=1；非 0 需检查接线/供电/波特率。
输出字段包括 gyro_*_dps、q_x/q_y/q_z/q_w、ready、who_am_i(=112=0x70)、
sample_count 以及全部 23 项诊断计数器。

### 4.3 imu_monitor.py —— IMU 实时监视

以固定频率（默认 50Hz）对 ID 200 单独发广播 SYNC READ 读地址 56 的 12 字节快速块，
终端实时刷新陀螺仪和四元数，可选 matplotlib 曲线或 CSV 记录。

```powershell
python Tools\imu_monitor.py --port COM6                 # 默认 50Hz，终端刷新
python Tools\imu_monitor.py --port COM6 --seconds 10    # 跑 10 秒后退出
python Tools\imu_monitor.py --port COM6 --plot          # 实时曲线窗口
python Tools\imu_monitor.py --port COM6 --csv imu.csv   # 记录有效样本
python Tools\imu_monitor.py --port COM6 --rate 100      # 改采样率
```

结束时打印 `ok/ck_err/timeout/hw_err` 统计；健康状态应 ck=0、timeout=0。

### 4.4 bus_monitor.py —— IMU + 多舵机联合监控（主力工具）

**一条广播 SYNC READ（地址 56、12 字节）同时读取 IMU 和全部舵机**，ID 列表自动按
`[舵机ID..., 200]` 排序（IMU 必须末位，见第 6 节）。默认还会对舵机做柔和的 demo 往返摆动，
退出时自动关闭所有由它开启的扭矩。

```powershell
# 扫描总线 + 仪表盘 + demo 摆动（默认 1536<->2560，周期 3s）
python Tools\bus_monitor.py --port COM6

# 只监控，不摆动（安全观察模式，推荐首次使用）
python Tools\bus_monitor.py --port COM6 --no-demo

# 实时曲线（IMU 陀螺仪/四元数）
python Tools\bus_monitor.py --port COM6 --plot

# 固定运行时长
python Tools\bus_monitor.py --port COM6 --seconds 20

# 只轮询指定舵机；--srv-id 0 表示总线上只有 IMU
python Tools\bus_monitor.py --port COM6 --srv-id 2,3 --no-demo
python Tools\bus_monitor.py --port COM6 --srv-id 0

# 调整 demo 摆动幅度/速度/周期
python Tools\bus_monitor.py --port COM6 --demo-lo 1024 --demo-hi 3072 `
  --demo-speed 300 --demo-period 2
```

终端每行设备显示：

- **IMU**：陀螺仪三轴（dps）、四元数 x/y/z/w、成功/请求计数。
- **舵机**：原始位置（0~4095）、角度（0~360°）、速度、负载、电压（0.1V）、温度、moving 标志。

demo 机制：
- 启动时对每个舵机单独写：扭矩使能(40)=1、加速度(41)=30、目标速度(46)、初始目标位置(42)。
- 之后每周期用**一条广播 SYNC WRITE（0x83，地址 42，2 字节）**统一下发目标位置。
- 若某舵机对 SYNC WRITE 无反应（不朝新目标运动），自动回退为对该舵机单独 WRITE，并在终端提示。
- Ctrl+C 退出或 `--seconds` 结束时，自动对所有使能过的舵机写扭矩=0。

> **安全提示**：不加 `--no-demo` 时舵机会真实转动。第一次使用请先空载、受限流电源，
> 并确认舵盘活动范围内无干涉。

## 5. 首次上板检查流程

1. 核对硬件版本与电源，先**单板限流上电**，检查 3.3V、无短路、无发热。
2. SWD 用 OpenOCD 烧录 hex（3.2 节），确认 verify OK、复位启动。
3. 接 J3 日志（COM5，115200，DTR+RTS）：见开机横幅、`ready=1`、WHO_AM_I=`0x70`。
   - 日志命令：`s` 立即打印状态、`l` 开关周期日志、`r` 请求重新初始化 IMU、`?` 帮助。
4. 转动/倾斜板子，观察 gyro 与 q16 数据随姿态变化。
5. 只接 IMU 板到总线，跑 `imu_probe.py`：退出码 0、ck/uart/spi/fifo 错误不增长。
6. 接一个飞特舵机，再跑 `servo_tool.py scan` 与 `bus_monitor.py --no-demo`，
   确认 IMU+舵机同帧读取稳定（成功率应接近 100%）。
7. 空载确认舵盘无干涉后，再用 `bus_monitor.py`（demo）做支撑状态下的联合摆动。

## 6. SYNC READ 的 ID 排序硬性规则

**主机 SYNC READ 的 ID 列表中，ID 200（IMU）禁止排在第一位，必须放在所有舵机之后
（中位或末位），或单独成组。**

- 实测（飞特舵机固件 3.46，1Mbps，30 轮×多种排序）：
  - `[200,2,3]`（IMU 首位）：仅 3/30 成功；
  - `[2,200,3]`（中位）：30/30；`[2,3,200]`（末位）：30/30；`[200]`（单独）：30/30。
- 原因：飞特舵机固件会"预测"自己的时隙，在前一设备应答起点约 180µs 后就提前开口；
  IMU 在首位时，舵机这一发恰好撞上 IMU 应答帧末尾的校验和字节。
- 本工程工具已自动遵守：`bus_monitor.py` 恒用 `[舵机ID..., 200]`；
  `imu_monitor.py` 只列 `[200]`。**自研主机（含 RK3566 侧移植）务必照此排序。**

## 7. 常见问题排查

| 现象 | 排查方向 |
|---|---|
| scan 看不到任何设备 | 端口是否为总线适配器（COM6）而非日志口；半双工方向；VDD_BUS/GND；1Mbps；是否有别的总线软件占用 |
| 只能看到舵机/只能看到 IMU | 供电；接线松动；波特率；IMU 板是否已烧飞特固件（旧 DXL2 固件不应答飞特帧） |
| 联合读丢帧、校验错误 | SYNC READ 列表里 200 是否被放到首位（必须末位/中位）；引线是否过长；加终端电阻 |
| COM5 打开但收不到日志 | DAP-Link CDC 需要 DTR+RTS 拉高；波特率 115200；J3.4/3.5 TX/RX 是否接反 |
| 工具提示无应答 | 总线上只能有一个主机；关闭 FD.exe/其他脚本；重新上电 |
| OpenOCD 报 cannot read IDR | 关闭 Keil µVision（独占 DAP-Link）；SWD 杜邦线重插；降速到 100kHz |
| UV4 烧录后行为没变 | UV4 命令行假成功，改用 OpenOCD（3.2 节） |
| demo 中舵机不动 | 看终端是否提示"回退到逐写"；检查模式/扭矩/速度寄存器；先跑 `servo_tool.py test` |
| 退出后舵机保持力矩 | 正常退出（Ctrl+C）会自动关扭矩；异常断电后用 `servo_tool.py write <id> 40 0` 手动关 |
