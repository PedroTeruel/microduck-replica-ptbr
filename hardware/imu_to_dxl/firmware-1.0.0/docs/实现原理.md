# 实现Princípio

本文Instruções IMU 板飞特 FT-SCS Firmware（v1.0.0） de 内部设计：Protocolo帧机、SYNC READ 排位防撞、
半双工物理层、IMU Dados链 e 寄存器映射。适合移植、二次开发 e 排障时阅读。

---

## 1. 系统定位 e 总体架构

### 1.1 定位

- Hardware：STM32G031F8P6（64MHz Cortex-M0+，64KB Flash / 8KB RAM）+ LSM6DSV16X 6 轴 IMU。
- 角色：飞特 FT-SCS 单线总线Superior de 一个**从机（ID=200）**， e 飞特Servo（ID 2、3…）共线，
  1Mbps、8N1、半双工。
- 数据契约对齐 GitHub `pollen-robotics/microduck` 的 duck-control（RK3566 侧）：
  陀螺仪三轴 + SFLP 浮点四元数 x/y/z（w 由主机恢复），50Hz SYNC READ Leitura。
  本工程不Execução Duck 姿态Algoritmos，也不做Instalação旋转——旋转由upstream duck-control Concluído。
- 裸机（无 RTOS），所有Protocolo逻辑在主循环Execução；ISR 只负责把字节带时间戳存入环形缓冲。

### 1.2 源Arquivo分层

| Arquivo | 职责 |
|---|---|
| `Core/Src/board.c` / `board_config.h` | 时钟(HSI16→PLL 64MHz)、USART2 总线、USART1 日志、SPI1、定时器微秒时基、IWDG、半双工收发、带时间戳接收环形缓冲 |
| `Core/Src/protocol.c` / `.h` | FT-SCS 帧解析、校验、指令分发、SYNC READ 顺序应答状态机（~410 行，无第三方代码） |
| `Core/Src/control_table.c` | 256 字节寄存器视图：IMU 快照打包、诊断块、可写 marker / IMU 重初始化命令 |
| `Core/Src/imu.c` | LSM6DSV16X 配置、FIFO 排空、SFLP 姿态解析、120Hz 采样、失效检测与自动恢复 |
| `Core/Src/main.c` | 主循环调度：收帧→协议轮询→IMU 轮询→日志，协议流量优先 |
| `Drivers/LSM6DSV16X/` | ST 官方寄存器驱动（仅寄存器定义层） |

Dados流：

```
LSM6DSV16X ─SPI 2MHz─► imu.c FIFO/SFLP ─► imu_snapshot_t
                                              │ (主循环里读，不撕裂)
USART2 ISR ─► 256B 环形缓冲(带 µs 时间戳) ─► protocol.c ─► control_table_read ─► 应答帧
                                              ▲
                                         proto_poll 在无总线活动时发射
```

## 2. FT-SCS Protocolo实现

### 2.1 帧格式

```
请求:  FF  FF  ID  LEN  INST  P_1 ... P_n        CK
应答:  FF  FF  ID  LEN  ERR   D_1 ... D_d        CK
        └─头─┘  └── LEN = 1(INST/ERR) + 参数/数据字节数 + 1(CK) = 总长-4 ──┘
```

- 帧总长 = 4 + LEN 字节。
- 校验e（单字节反码e）：

  `CK = ~( ID + LEN + INST/ERR + Σ(参数/数据) ) & 0xFF`

  只覆盖 ID 起的字节，不含两个 `0xFF` 帧头。
- 广播 ID = 254（0xFE）；合法从机 ID = 1..252。

Validação向量（可usado para移植自测）：

| 帧 | 字节 |
|---|---|
| PING ID200 请求 | `FF FF C8 02 01 34` |
| PING 应答（ERR=0） | `FF FF C8 02 00 35`（注意应答 CK 与请求不同） |
| READ 56/12 请求 | `FF FF C8 04 02 38 0C ED` |
| READ 12 字节应答 | LEN = 12 + 2 = 14 |

### 2.2 指令集

| INST | 名称 | Parâmetros | 应答 |
|---|---|---|---|
| 0x01 | PING | 无 | 仅单播应答空状态；**广播 PING 静默**（总线SuperiorServo会答，IMU 不凑热闹） |
| 0x02 | READ | addr(u8), count(u8) | ERR + count 字节；count 1..128，addr+count ≤ 256；不接受广播 |
| 0x03 | WRITE | addr(u8), data… | 单播回 ERR；广播静默 |
| 0x82 | SYNC READ | addr, count, id…（发往广播） | 各从机按列表顺序应答 |
| 0x83 | SYNC WRITE | addr, dlen, [id, dlen字节]… | 静默执行，不应答 |
| 其它 | — | — | 一律静默丢弃 |

不实现 Reg Write/Action/Bulk、无 Flash 写、ID  e 波特率**固定不可改**（写 5/6 返回访问错误）、
**无返回延迟**（应答立即排程）。错误码兼容飞特语义：1 RESULT、2 INSTRUCTION、3 CRC、
4 RANGE、5 LENGTH、6 LIMIT、7 ACCESS。

帧大小护栏：`PROTO_MAX_READ=128`；可接受的最大 LEN = 132（128 数据 READ 应答 LEN=130，
128 字节单段 SYNC WRITE LEN=132）。更大 de  LEN 立即判为噪声，避免吞掉后续整段总线流量。

### 2.3 接收状态机（proto_feed，每字节调用）

1. 搜索两个连续 `0xFF`；允许多余前导 FF；ID=0/255 判畸形重启搜索。
2. 收到 LEN 立即算出整帧长度（4+LEN），之后按长度收齐——不在Dados里找帧头。
3. 收齐后校验和正确 → `rx_packets++` → `execute()`；错误 → `checksum_errors++`，
   并从本帧尾部回扫 `0xFF`，尝试把误短帧中嵌套的下一帧头抢救出来（重同步）。
4. 字节间间隔超 1500µs（`PROTO_BYTE_TIMEOUT_US`）丢弃半截帧，计 `receive_timeouts`。
5. **时间戳用 ISR 入队时刻**（不是主循环取出时刻），保证排位判断 de 时间精度。

### 2.4 发射 e "总线空闲"原则

应答先在 `tx[]` 组好帧并标记排程（`schedule_reply`），真正发送在 `proto_poll()`：

- `pending=1`（到点可发）：仅当 `rx_length==0`（当前没有正在接收的帧）且
  距离排程时刻不超过 2000µs（`PROTO_REPLY_EXPIRY_US`）才发送，否则放弃本轮（让位避让）。
- `pending=1` 期间一旦收到任何新字节，立即取消（`cancelled_replies++`）——
  任何别 de 设备开口都意味着总线已不属于自己。
- 主循环在调用 `proto_poll` **之前**先排空接收环形缓冲，这是以上判断成立的前提。

## 3. SYNC READ 顺序应答 e 防撞（核心机制）

### 3.1 问题：没有时隙令牌 de 共享总线

FT-SCS 的 SYNC READ 一帧带完整 ID 列表（如 `[2,3,200]`），每个从机都能看到全部 ID，
应答要求"按列表顺序、互不碰撞"。但Protocolo没有任何显式令牌：主机不逐个点名，
从机只能自己判断"轮到我了"。

飞特ServoFirmware（实测 3.46） de 做法是**预测时隙**：它并不等前一设备应答结束，
而是在"前一帧起点约 +180µs"就提前开始发送自己 de 应答。IMU 板必须 e 这种行为共存。

### 3.2 排位状态机

固件遍历 ID 列表找到自己的位置 i（`protocol.c` SYNC READ 分发，约 L260-263）：

- **i 是首位（i==2，列表第 1 个）**：`schedule_reply(preceding=-1)` → `pending=1`，
  立即排程发送。
- **非首位**：记住"前一位 ID" = 列表中自己前面那个 ID，`pending=2`。
  之后在 `execute()` 里**嗅探总线**：只有看到来自该 preceding ID 的、校验合法的帧，
  才把 `pending=2 → pending=1`（"前一设备已经发过，轮到我"）。
  - 25ms（`PROTO_TRANSACTION_TIMEOUT_US`）内没等到前一设备的合法帧 → 放弃本轮，
    避免乱抢。
  - 等待期间若看到发给自己或广播 de 新主机帧 → 本轮作废（新一轮事务开始）。

合法 ID 列表要求：至少 1 个 ID、全部 1..252、不允许重复；列表畸形时即使含有自己也不应答。

### 3.3 实测碰撞 e 硬性排序规则

| 主机列表 | IMU Sucesso率（30 轮） | Instruções |
|---|---|---|
| `[200, 2, 3]`（IMU 首位） | **3/30** | 舵机在 IMU 帧起点 +180µs 提前开口，恰好撞 IMU 校验和字节 |
| `[2, 200, 3]`（中位） | 30/30 | IMU 听到 ID2 合法帧后再发 |
| `[2, 3, 200]`（末位） | 30/30 | 同上，preceding=3 |
| `[200]`（单独） | 30/30 | 无后续舵机，无碰撞 |

**结论：主机必须把 ID 200 放在所有Servo之后（ em 位/末位），或单独列组；禁止首位。**
本工程 `bus_monitor.py` 恒用 `[舵机..., 200]`，`imu_monitor.py` 只列 `[200]`。
（HistóricoSuperior试过人为加 506µs slot delay，反而更差，已移除。）

### 3.4 50Hz 时间预算（为什么不是时间瓶颈）

1Mbps、每字 10 bit（1 起始+8 Dados+1 停止）：

- SYNC READ Por favor求（以 3 设备计，11 字节）≈ 110µs；
- 每个 12 字节Dados应答（18 字节）≈ 180µs；
- 一轮三设备总占用 ≈ 110 + 3×180 ≈ **650µs**，相对 50Hz  de  20ms 周期仅占 **3.3%**。

裕量极大——真正 de 约束不是时间不够，而是Servo"预测发送"造成 de Eletrônica碰撞，
因此解决办法是排序 + 嗅探让位，而不是压缩时隙。

## 4. 半双工物理层

板上用收发缓冲器挂单线总线（见 `board.c board_bus_send`）：

- **PA1 = 1OE#（方向使能，低有效）**：发送前拉低驱动总线，发送结束拉高释放。
- **PB7 = RX_EN**：发送期间拉低，**抑制本机自己 de 回显**（否则会收到自己发 de 帧）；
  PA3 接收Superior拉保持。
- 发送流程（关 USART2  em 断保护关键段）：
  1. 发送前再次检查无总线活动（`BUSY/RXNE/ORE/FE/NE/PE` 全清、环形缓冲已空），
     有活动则放弃本次发射，计 `tx_busy_drops`（绝不覆盖正在收到的字节）；
  2. PB7 抑回显 → 清 TC 标志 → PA1 拉低；
  3. 逐字节写 TDR，最后**等 TC（发送Concluído，含最后一个停止位）**而不是 TXE；
  4. 才释放 PA1、恢复接收；带超时保护（按字节数算上限），超时计 `tx_timeouts`。
- 接收：USART2  em 断逐字节入 256 字节环形缓冲（2  de 幂），记录微秒时间戳；
  溢出计 `rx_overflows`（不覆盖旧数据）；硬件错误计 `uart_errors` 并上报 `bus_fault`，
  主循环据此调 `proto_reset_receiver()` 复位帧机。

这种"组帧—等空闲—原子发射—等 TC—释放" de 时序保证了应答Completo出现在线Superior，
且不会 e 入帧、 e 本机回显互相污染。

## 5. 寄存器映射（ID 200）

所有多字节整数**小端**。0..9 由Protocolo层拥有（只读、固定值）；其余由 control_table 即时打包。

### 5.1 身份 e Configuração区（0..9）

| 地址 | 长度 | Conteúdo |
|---|---|---|
| 0..1 | 2 | 型号 0x4D44（小端：44 4D） |
| 2 | 1 | FirmwareVersão = 1 |
| 5 | 1 | ID = 200（固定） |
| 6 | 1 | 波特率码 = 0（飞特码 0 = 1Mbps，固定） |
| 9 | 1 | 返回延迟 = 0（立即应答） |
| 3,4,7,8 | — | Preservado，读 0；0..9 整区只读 |

### 5.2 56 起 de 快速块（ e Servo状态块同址，SYNC READ 56/12  de 核心）

| 地址 | 长度 | Conteúdo | 量程/编码 |
|---|---|---|---|
| 56,58,60 | 3×i16 | 陀螺仪 gx,gy,gz（传感器轴系original计数） | ±500 dps，**17.5 mdps/LSB** |
| 62,64,66 | 3×u16 | 四元数 qx,qy,qz（**IEEE-754 fp16**，SFLP original输出） | w 主机恢复 |
| 68,70,72 | 3×i16 | 加速度 ax,ay,az | ±4g，0.122 mg/LSB |
| 74 | 1 | sample_count 低字节 | — |
| 75 | 1 | 状态标志：bit0 ready、bit1 configured、bit2 error | — |
| 76 | 1 | WHO_AM_I = 0x70（112） | — |
| 77 | 1 | IMU 错误码（见 imu.h 枚举） | — |
| 78 | 1 | 时钟状态 | — |
| 79 | 1 | 看门狗使能 = 1 | — |
| 80..83 | u32 | sample_count（接受 de  SFLP 记录数，非主机Leitura次数） | — |
| 84 | 1 | **user_marker，唯一可自由读写 de  RAM 字节**（板Superior无 LED） | — |
| 240 | 1 | 写 0xA5 → Por favor求重新初始化 IMU；其它访问拒绝 | — |

**为什么快速块放在 56**：飞特Servo在同地址 56 提供位置/速度/负载/电压/温度/运动状态
（pos i16、spd i16 含方向位、load i16、电压在 62 为 0.1V、温度 63、moving 66）。
于是主机**一条 `SYNC READ 56/12`** 就能同时取走 IMU 的 gyro+四元数和每个舵机的状态，
设备类型靠 ID 区分（200 是 IMU，其余按Servo解码）。IMU 块 de Conteúdo则承接 microduck
旧 DXL2@124 Dados块（gyro + SFLP xyz），主机Dados契约Inalterado。

### 5.3 90..185 诊断块（24×u32，96 字节，revision 1）

imu_probe 验收时读 90/96。健康系统关键计数器应长期为 0 或仅单调反映真实事件：

| 偏移 | 计数器 | 偏移 | 计数器 |
|---|---|---|---|
| 90 | gyro_count | 138 | malformed_packets |
| 94 | accel_count | 142 | rx_timeouts |
| 98 | uptime_ms | 146 | rx_packets（合法帧） |
| 102 | gyro Dados年龄 ms | 150 | tx_packets |
| 106 | 四元数年龄 ms | 154 | cancelled_replies（让位次数） |
| 110 | spi_errors | 158 | reset_flags |
| 114 | fifo_overflows | 162 | clock_hz（64000000） |
| 118 | invalid_quaternions | 166 | tx_timeouts |
| 122 | recovery_count（IMU 重启次数） | 170 | log_dropped（日志丢行） |
| 126 | rx_overflows（环形缓冲溢出） | 174 | 诊断表Versão = 1 |
| 130 | uart_errors | 178 | tx_busy_drops（忙时放弃发射） |
| 134 | checksum_errors | 182 | reserved（0） |

`control_table_read` 每次调用在栈上构造一张 256 字节全零表、取一次 IMU 快照后整体打包，
因此一次 READ 得到 de Dados天然不撕裂（采集 e 回调同在主循环，无并发）。

## 6. IMU Dados链（imu.c）

1. **SPI1，模式 3，2MHz**（PCLK/32）；Configuração LSM6DSV16X：陀螺/加速度 ODR 120Hz，
   陀螺 ±500dps、加速度 ±4g，开启 FIFO  e  SFLP（Sensor Fusion Low Power）姿态输出。
2. **120Hz 采样、50Hz 消费**：每个主机周期（20ms）内有 2 次以Enviar感器Atualização，
   `imu_poll` 一次排空 FIFO（预算 16 帧），取最新有效记录，天然抗抖动。
3. **四元数编码**：直接采用 SFLP 输出 de  IEEE-754 半精度（fp16）qx/qy/qz；
   主机端恢复非负 `qw = sqrt(max(0, 1 - qx² - qy² - qz²))`。固件只传 3 个分量省带宽，
   符号约定由upstream duck-control 持有。
4. **就绪/失效语义**：
   - 未就绪时 gyro  e 四元数字节**全零**（upstream沿用 de  not-ready 标记），
     加速度 e 计数器仍可读，usado para诊断；
   - gyro/quat Dados年龄超 100ms 判 stale；FIFO、SPI、WHO_AM_I、Configuração、四元数合法性
     各有独立错误码（imu_error_t）。
5. **自动恢复**：失效后按 1000ms 退避重新走复位→WHO_AM_I→Configuração流程，
   启动超时 1500ms；恢复不清除生命周期计数器，`recovery_count` 记录次数。
   也可由主机写 240=0xA5 或日志口按 `r` 主动请求重初始化。
6. 主循环只在"无正在接收的指令、且无待发应答"时才执行 `imu_poll`，协议流量绝对优先。

## 7. 主循环 e 工程细节

```c
board_init(); proto_init(..., control_table_read/write, send_packet); imu_init();
for (;;) {
    if (board_bus_take_fault()) proto_reset_receiver();      // UART 故障后复位帧机
    while (board_bus_pop(&byte, &ts)) proto_feed(..., ts);   // 先排空 RX（用入队时间戳）
    proto_poll(now_us);                                      // 到点且空闲才发射
    if (rx_length==0 && pending==0) {                        // 协议空闲才做传感器/日志
        imu_poll();
        处理日志口命令(s/l/r/?); 每秒打印状态行;
    }
    board_watchdog_feed();                                   // IWDG
}
```

- 日志走独立 USART1（115200），带 512B 发送环形缓冲；日志拥堵只计 `log_dropped`，
  绝不阻塞Protocolo。DAP-Link CDC 需 DTR/RTS 拉高才有输出。
- IWDG 常开（`BOARD_ENABLE_WATCHDOG=1`）；时钟 HSI16→PLL 64MHz，不依赖外部晶振贴装。
- 所有构建期板级选项集中在 `board_config.h`（波特率、RX_EN 脚、SPI 速率、日志交换等）。
- 构建：`Tools/build.ps1` 调 ArmClang 命令行，产物与 build.json 在 `Build/`；
  链接脚本 `MDK-ARM/imu_to_dxl.sct`。Keil 只保留 DAP 一套工程（`imu_to_dxl_dap.uvprojx`）。

## 8. 主机Ferramentas如何复用同一契约

`Tools/` 下 Python 工具是协议的参考实现，可直接被自研主机参考：

- `imu_monitor.py` 导出帧原语 `ft_frame() / checksum() / build_sync_read() / parse_reply()`；
  解析切片 `body = buf[2 : 4+len]`、按 4+len 步进，与固件帧机严格对应。
- `bus_monitor.py` 一条广播 SYNC READ 56/12、列表 `[舵机..., 200]`，20ms 周期；
  目标位置用一条广播 SYNC WRITE 0x83（addr 42, 2B）统一Inferior发，
  对不响应 SYNC WRITE  de Servo自动逐写回退；每轮收帧前清解析缓冲 e 串口输入缓冲，
  防止迟到帧污染Inferior一轮。
- 主机侧Dados解码：gyro×0.0175 得 dps；fp16→float32 后恢复 qw；
  ready/whoami/年龄 e 诊断计数器usado para健康判定。

移植到 RK3566 或其它Controle器时，必须同时照搬两条硬约定：
**(1) SYNC READ 列表 ID 200 置于Servo之后；(2) gyro 17.5mdps/LSB、四元数 fp16、qw 主机恢复。**
